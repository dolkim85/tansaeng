| 라벨 예상 | 연결 대상 |
|---|---|

| RS485 A / B / GND | 메인 노드의 RS485 A / B / GND (A-A, B-B로 연결, 극성 반대로 연결해도 대개 무응답일 뿐 손상은 없음) |

RS485 종단저항: 배선 길이가 길거나 통신이 불안정하면 보드의 120Ω 종단저항 점퍼를 활성화(양쪽 끝 노드 중 하나 또는 둘 다, 실물 테스트로 판단).

## 유량계(YF-B10-S) 배선 — 팔 노드로 이전 (2026-08-23)

### ⚠️ 팔 노드 GPIO 미확정 — `NEEDS_HARDWARE_CONFIRMATION`

`docs/hardware-verification.md` "2-1"절 참고. Relay-6CH에는 Pico HAT 호환 40핀 헤더가 2개 있고 여유 GPIO를 노출한다는 것까지는 확인했지만, **정확히 어느 GPIO가 헤더의 어느 위치에 나오는지 근거를 찾지 못했습니다.** 임의로 정하지 않았습니다.

**현장에서 확인/촬영해주실 것:**
1. Relay-6CH 보드의 Pico HAT 헤더 2개 실크스크린(핀 번호/GPIO 라벨이 인쇄돼 있는지) 클로즈업 사진
2. 가능하면 Waveshare 위키(`waveshare.com/wiki/ESP32-S3-Relay-6CH`) 페이지 하단의 회로도(schematic) PDF 다운로드 링크 캡처
3. 위 두 가지가 어려우면, 빈 핀에 멀티미터 연속성 테스트로 어느 물리적 위치가 어느 방향 배선인지만이라도 확인

확인되면 `firmware/arm_relay_6ch/config.h`의 `FLOW_PULSE_PIN`에 그 값을 넣으면 됩니다(코드는 이미 이 값을 설정 하나로 분리해뒀습니다 — 확인 전에는 빌드 시 `#error`로 막혀 실수로 잘못된 핀을 쓰는 걸 방지합니다).

### 유량계 전기적 특성 (검색 근거 — 실측 필요)

여러 독립 판매처/포럼에서 공통적으로 확인되는 값입니다(공식 데이터시트 PDF는 스캔 품질이 낮아 직접 인용은 못 했습니다):

| 항목 | 값 | 비고 |
|---|---|---|
| 공급전압 | DC 3.5~24V (권장 5~15V) | **현장 실제 공급전압을 반드시 실측** — 기존 사고(ctlr-0004 GPIO4 24V 직결 손상)를 보면 이 현장은 24V에 가까운 전압을 쓰고 있었을 가능성이 있음 |
| 신호 출력 방식 | **오픈컬렉터(NPN)** — 신호선 자체에 전압을 밀어내지 않고, 펄스 발생 시 내부 트랜지스터가 GND로 전류를 끌어당김(싱크)만 함(active-low) | GPIO에 전압을 직접 읽히는 방식이 아니라 **전류를 끌어가는 방식**이므로, 아래 절연회로에서는 별도 풀업 저항 대신 **PC817 LED 자체가 풀업 부하** 역할을 겸함(2026-08-23 회로 재검증 — "권장 절연 입력회로" 절 참고) |
| 배선 색상 | 빨강=공급+, 검정=GND, 노랑=펄스신호 | ⚠️ **색상만 믿지 말 것** — 반드시 실물 라벨/스티커나 판매처 데이터시트로 재확인. 다른 배치는 색상이 다를 수 있음 |
| 최대 펄스 주파수 | 약 100Hz 이하(유량 범위 1~50L/min 기준) | 기존 계산식(`Frequency(Hz)=10×Q-5`)과 일치하는 범위 |

**실측 없이 이 표만 믿고 최종 배선을 확정하지 마세요.** 배선 전 반드시 다음을 멀티미터/오실로스코프로 확인:
1. 센서에 실제로 인가되는 공급전압(빨강-검정 사이, 전원 켠 상태에서 실측)
2. 노랑(신호)선을 아무것도 안 물린 상태에서 뜨는지 안 뜨는지(오픈컬렉터라면 풀업 없이는 신호가 붕 떠서 안정적으로 안 읽힘 — 정상)
3. (임시 벤치테스트용 풀업 — 최종 회로의 R1 아님, 최종 회로는 별도 풀업 없이 PC817 LED가 그 역할을 겸함) 신호선에 임시로 풀업 저항 하나만 걸고 물을 흘렸을 때 전압이 0V~풀업전압 사이에서 스퀘어파로 스윙하는지 오실로스코프/멀티미터로 확인 — 센서 오픈컬렉터가 실제로 정상 동작하는지만 보는 예비 점검

### 권장 절연 입력회로 (2026-08-23 재검증 — 회로 오류 수정)

**핵심 원칙: 센서 쪽 전압(최대 24V일 수 있음)이 ESP32 GPIO(3.3V 허용)에 절대 직접 닿으면 안 됩니다.** 기존 사고가 정확히 이 실수(24V를 GPIO4에 직결)로 발생했습니다. 포토커플러로 완전히 전기적 분리를 권장합니다 — 마침 Relay-6CH 보드 자체도 릴레이 절연에 **PC817 포토커플러**를 이미 쓰고 있어([CNX Software 확인](https://www.cnx-software.com/2024/04/02/6-channel-esp32-s3-wifi-relay-module-rs485-raspberry-pi-pico-hat/)), 같은 부품으로 통일하면 조달/신뢰성 면에서 유리합니다.

> ⚠️ **이전 버전 회로 오류 수정**: 이전 버전은 신호선에 별도 풀업 R1(10kΩ)을 두고, 그 뒤에 다시 LED 전류제한 R2를 직렬로 연결했습니다. 이렇게 하면 센서가 쉬고 있을 때(오픈컬렉터 OFF) 전류가 `Vs → R1 → R2 → LED → GND` 경로로 흘러 **R1+R2가 직렬**이 되어 LED 전류가 목표치(10mA)의 3~10분의 1 수준(예: 5V에서 약 0.37mA)으로 떨어지고, 반대로 센서가 펄스를 낼 때(OFF→GND로 싱크)는 R1에서 대부분의 전압이 걸려 LED가 꺼지는 **논리가 뒤바뀐 회로**였습니다(당시 `FLOW_PULSE_EDGE=FALLING` 기본값과도 맞지 않았음). 아래는 R1을 없애고 **PC817 LED 자체를 풀업 부하로 겸용**하는, 오픈컬렉터 싱크 회로에 맞는 정상 구조입니다.

**회로 종류**: 이것은 센서가 전압을 밀어내는 "전압 출력" 회로가 **아니라**, 센서 내부 NPN 트랜지스터가 GND로 전류를 끌어당기는(싱크하는) **오픈컬렉터 전류 싱크 회로**입니다. LED가 켜지고 꺼지는 것은 전압이 아니라 "전류 경로가 이어져 있는가"로 결정됩니다.

```text
[센서 공급전원 Vs] ──┬── 유량계 빨강(+)
                     │
                    R2(전류제한 겸 풀업 부하, 아래 표)
                     │
                 PC817 LED 애노드
                     │
                 PC817 LED 캐소드
                     │
[유량계 노랑(신호) = 센서 내부 오픈컬렉터 출력] ── 위 LED 캐소드에 직결

[유량계 검정(GND)] ── Vs 리턴(센서측 공통 GND, 팔 노드 GND와 분리)

PC817 출력(포토트랜지스터) 쪽:
  ESP32 3.3V ── R3(풀업, 예: 10kΩ) ── 팔 노드 FLOW_PULSE_PIN
  PC817 이미터 ── 팔 노드 GND (센서 GND와 분리됨 — 이게 절연의 핵심)
  PC817 컬렉터 ── FLOW_PULSE_PIN에 연결
```

**전류 경로 (2가지 상태)**:
- **평상시(펄스 없음)**: 센서 내부 트랜지스터 OFF(컬렉터 오픈, 전류 경로 끊김) → `Vs → R2 → LED` 경로에 전류가 흐를 곳이 없음 → LED OFF → 포토트랜지스터 OFF → `FLOW_PULSE_PIN`은 R3에 의해 **3.3V(HIGH)** 유지
- **펄스 발생 시**: 센서 내부 트랜지스터 ON, 노랑선을 GND로 싱크 → `Vs → R2 → LED → 센서 내부 트랜지스터 → GND` 경로로 전류가 흐름 → LED ON → 포토트랜지스터 ON → `FLOW_PULSE_PIN`이 GND 쪽으로 끌려 **LOW**
- 따라서 GPIO에서는 "평소 HIGH, 펄스 시 LOW로 떨어지는" 파형이 관측됨 — **`config.h`의 `FLOW_PULSE_EDGE = FALLING` 기본값과 정확히 일치**(수정 불필요, 이 회로 재검증으로 확인됨)

| 부품 | 값 | 산정 근거 |
|---|---|---|
| R2 (LED 전류제한 겸 풀업 부하) | **5V→390Ω / 12V→1kΩ / 24V→2.2kΩ** (아래 "저항값 재계산" 절 참고) | `(Vs - Vf) / I목표`, Vf=1.2V(PC817 순방향전압 근사), I목표=10mA |
| R3 (포토트랜지스터 풀업) | 10kΩ, 1/4W (또는 팔 노드 내부 `INPUT_PULLUP` 활용 가능) | ESP32 로직측, 3.3V만 취급하므로 GPIO에 5V 이상이 들어갈 경로 없음 |
| 포토커플러 | PC817 또는 동급(전류전달비 CTR ≥ 50%, 스위칭 주파수 수 kHz 이상 — YF-B10-S 최대 100Hz에 충분히 여유) | 보드에 이미 쓰이는 부품과 통일 |
| (선택) 필터 커패시터 | 신호선-GND 사이 100pF~1nF | 노이즈로 인한 오카운트가 관측되면 추가 (기존 GPIO16 노이즈 사고 이력 고려) |
| (선택) 슈미트 트리거 버퍼 | 74HC14 등 | 배선이 길거나(수 미터 이상) 포토커플러 출력 엣지가 느려서 글리치가 보이면 추가 검토 |

**R1(신호 풀업) 관련**: 위 회로에서는 별도 R1이 필요 없습니다. LED+R2 자체가 센서 오픈컬렉터 출력의 풀업 부하 역할을 겸하기 때문입니다(오픈컬렉터를 옵토커플러로 격리할 때의 표준 방식). 굳이 R1을 추가하면 위에서 설명한 "전류 부족/논리 반전" 문제가 재발하므로 **추가하지 마세요**.

### 저항값(R2) 재계산 — 공급전압별

PC817 LED 순방향전압을 Vf≈1.2V(데이터시트 typ. 근사치)로, 목표 LED 전류를 10mA(안정적 스위칭을 위한 설계 여유치, PC817 CTR 시험조건과 근접)로 두고 계산했습니다.

```text
공급전압: 5V
PC817 LED 순방향 전압 가정: Vf ≈ 1.2V
목표 LED 전류: 10mA
계산 저항: (5 - 1.2) / 0.01 = 380Ω
선정한 표준 저항: 390Ω (E24 표준값)
저항 소비전력: I=(5-1.2)/390≈9.74mA, P=I²R≈0.037W(37mW)
최소 권장 정격: 1/4W(0.25W)로 충분 (여유 약 6.7배)
```

```text
공급전압: 12V
PC817 LED 순방향 전압 가정: Vf ≈ 1.2V
목표 LED 전류: 10mA
계산 저항: (12 - 1.2) / 0.01 = 1080Ω
선정한 표준 저항: 1kΩ (E24 표준값, 더 정밀하게 맞추려면 1.1kΩ도 가능)
저항 소비전력: I=(12-1.2)/1000≈10.8mA, P=I²R≈0.117W(117mW)
최소 권장 정격: 1/4W(0.25W)는 여유 약 2.1배로 사용은 가능하나, 방열 여유를 위해 1/2W(0.5W) 권장
```

```text
공급전압: 24V
PC817 LED 순방향 전압 가정: Vf ≈ 1.2V
목표 LED 전류: 10mA
계산 저항: (24 - 1.2) / 0.01 = 2280Ω
선정한 표준 저항: 2.2kΩ (E12/E24 표준값)
저항 소비전력: I=(24-1.2)/2200≈10.36mA, P=I²R≈0.236W(236mW)
최소 권장 정격: 1/4W(0.25W)는 정격의 약 94%까지 차서 여유가 거의 없어 **부적합**.
                최소 1/2W(0.5W) 이상 필수, 여유를 두려면 1W 권장
```

**검증 결론**: `5V=390Ω / 12V=1kΩ / 24V=2.2kΩ` 저항값 자체는 타당합니다. 다만 **와트수 지정이 이전 문서에 빠져 있었고**, 특히 24V 조건에서 1/4W 저항을 쓰면 정격에 거의 딱 맞아(94%) 장기적으로 열화·고장 위험이 있으므로 12V/24V 구간은 **1/2W 이상**을 사용하세요. 실제 배선 전 반드시 실측한 Vs로 위 공식을 다시 계산해 확인하세요(현장 전압이 표와 다를 수 있음 — `NEEDS_HARDWARE_CONFIRMATION`).

**전원 공통(GND) 여부**: 이 회로는 포토커플러로 센서측(Vs, GND_sensor)과 로직측(3.3V, GND_logic=팔 노드 GND)을 **완전히 분리**합니다. 센서 전원이 별도 어댑터라면 GND를 팔 노드와 공통으로 묶을 필요가 없습니다(오히려 안 묶는 게 절연의 의미가 삽니다). 팔 노드 전원과 센서 전원이 같은 어댑터/레일을 쓰는 경우라도 이 회로 구조상 문제는 없습니다. ESP32 GPIO(`FLOW_PULSE_PIN`)는 포토트랜지스터 쪽 3.3V 회로에만 연결되므로, 센서측에 5V든 24V든 어떤 전압이 걸려도 GPIO에는 물리적으로 도달할 경로가 없습니다.

### 현장 시험 순서 (반드시 이 순서대로)

1. 유량계 신호 전압 확인 (위 "실측" 3단계)
2. 절연 입력회로만 단독으로 벤치 테스트 (팔 노드 GPIO 대신 LED+저항으로 신호가 토글되는지 육안 확인)
3. 팔 노드에서 펄스 카운트 확인 (시리얼 로그, `test/flow_pulse_generator`로 알려진 주파수 입력 비교)
4. Modbus 레지스터 값 확인 (메인 노드가 팔 노드에서 읽어온 값이 시리얼 로그에 맞게 나오는지)
5. 메인 노드 MQTT 발행값 확인 (기존과 동일한 토픽/단위로 나오는지)
6. **기존 ESP32(GPIO16)의 값과 나란히 비교** — 같은 유량에서 비슷한 값이 나오는지(완전히 새 회로라 오차가 있을 수 있음, 허용 오차는 현장에서 판단)
7. 밸브는 MANUAL로 개별 시험 (유량계와 무관하게 항상 먼저 확인)
8. 이상 시 기존 ESP32 배선으로 롤백 (유량계 신호선은 아래 "전환 절차" 참고 — Y자 병렬연결 금지, 한쪽만 연결)

### ⚠️ 유량계 신호선 Y자 병렬연결 금지

이전 버전 문서에서는 "유량계는 입력이라 기존 ESP32와 새 시스템에 동시에 연결해도 안전하다"고 적었으나, **이번 절연회로 설계 전까지는 이 가정을 철회합니다.** 양쪽 입력회로(기존 ESP32의 GPIO16 직결 방식과 새 팔 노드의 절연회로)가 전기적으로 다르고, 특히 기존 쪽은 과거 손상 이력(GPIO4 24V 직결)이 있어 회로 상태가 불확실합니다. 두 입력을 동시에 물리면 한쪽의 예상치 못한 임피던스나 고장이 다른 쪽 신호 품질에 영향을 줄 수 있습니다.

**기본 전환 절차는 한쪽만 연결하는 방식으로 진행하세요**: 위 1~6단계로 새 회로를 완전히 검증한 뒤에만 신호선을 새 팔 노드 쪽으로 옮기고, 기존 ESP32 쪽은 연결 해제 상태로 대기시킵니다(전체 롤백 시 다시 옮기면 됨).

## 현장 전환 및 롤백 절차 (실제 밸브 배선 시 반드시 따를 것)

MQTT 토픽이 기존과 완전히 동일하므로, 서버/UI는 어느 쪽 하드웨어가 붙어있든 신경 쓰지 않습니다. "한 번에 교체"가 아니라 **되돌릴 수 있는 단계적 전환**으로 진행합니다.

**1단계 — 책상 위 벤치 테스트**
실제 밸브 연결 전, 두 새 보드만 따로 놓고 이더넷+RS485+MQTT 통신을 확인합니다. 릴레이는 LED나 멀티미터로만 확인합니다. 이 단계는 실패해도 농장 운영에 영향이 없습니다.

**2단계 — 병행 배치**
1. 기존 WiFi ESP32(`ctlr-0004`)의 전원을 뽑아 옆에 대기시킵니다(폐기 금지).
2. 새 시스템을 실제 밸브 배선에 연결합니다.
3. **MANUAL 모드로만** 먼저 테스트합니다(AUTO는 아직 켜지 않음). 웹 UI에서 밸브 ON/OFF를 눌러 실제로 열리고 닫히는지, 90초 안전타임아웃이 동작하는지 확인합니다.
4. 이 단계는 반드시 사람이 현장에서 지켜보면서 진행합니다(무인 방치 금지).

**3단계 — 문제 발생 시 즉시 롤백**
새 보드 전원을 내리고, 기존 WiFi ESP32 전원을 다시 연결합니다. 밸브 커넥터가 호환되도록 미리 배선해두면 몇 분 안에 원상복구됩니다. 서버/UI는 아무것도 바꿀 필요가 없습니다(토픽이 동일하므로).

**4단계 — 안정 확인 후에만 AUTO 전환**
MANUAL로 최소 며칠간 문제없이 동작하는 것을 확인한 뒤에만 AUTO를 켭니다.

**5단계 — 로컬재생 기능은 가장 마지막에**
구역A 로컬재생(`localReplay`, 인터넷 끊김 시 자동재생)은 기본 유선 명령 실행이 충분히 안정적임을 확인한 뒤에 별도로 검증합니다. 한 번에 여러 새 기능을 동시에 켜면 문제가 생겼을 때 원인 파악이 어렵습니다.

**추가 권장**: 가능하면 배관에 전자밸브와 별개인 수동 개폐 밸브를 하나 더 두면, 전자적으로 문제가 생겨도 물리적으로 막을 수 있는 최후의 안전장치가 됩니다.
