# 단계별 시험 절차

각 항목은 실물 보드가 있어야 확인 가능합니다(`NEEDS_HARDWARE_TEST`). 실제 결과를 이 표에 채워가며 진행하세요.

## 단계 1: 보드 단독 시험

| 항목 | 기대 결과 | 실제 결과 |
|---|---|---|
| Relay-6CH CH1~CH6 1초 간격 순차 ON/OFF | 릴레이 클릭음/LED로 순서대로 확인 | |
| 릴레이 활성 레벨 확인 | active-high로 추정(문서상) — 실측 확인 | |
| 재부팅 중 릴레이 순간 ON 여부 | 순간적으로도 켜지지 않아야 함 | |
| 메인 보드 W5500 DHCP 연결 | IP 할당받음, 시리얼로 확인 | |
| 이더넷 케이블 단절/복구 | 단절 시 감지, 재연결 시 자동 복구(재부팅 없이) | |
| 메인 보드 DI1 입력 상태 확인 | 신호 없을 때 기본 레벨(HIGH, active-low 특성상) 확인 | |

## 단계 2: RS485 시험

| 항목 | 기대 결과 | 실제 결과 |
|---|---|---|
| 짧은 선으로 A-A, B-B 연결 | | |
| Master가 Slave 주소 1 폴링 | 정상 응답 | |
| CH1~CH3 ON/OFF 명령 + 읽기 검증 | 명령대로 동작 + 상태 일치 확인 | |
| CRC 오류/응답 타임아웃 시험 | 재시도 후 fault 보고 | |
| RS485 선 분리 → 10초 내 전체 OFF | 팔 노드 자체 워치독 동작 | |
| RS485 재연결 → 상태 재동기화 | 메인이 현재 목표상태 재전송 | |

## 단계 3: MQTT 및 Ethernet 시험

| 항목 | 기대 결과 | 실제 결과 |
|---|---|---|
| 기존 MQTT 토픽으로 CH1~CH3 제어 | 기존 UI에서 그대로 동작 | |
| Ethernet 분리 중 RS485/안전타이머 계속 동작 | | |
| 케이블 재연결 후 자동 MQTT 복구 | 재부팅 없이 | |
| 잘못된 MQTT 명령 무시 | 로그만 남고 무시 | |
| MQTT 장애로 재부팅 안 하는지 | | |

## 단계 4: 유량계 시험

| 항목 | 기대 결과 | 실제 결과 |
|---|---|---|
| 알려진 주파수(1/10/50/100Hz) 펄스 입력 | `test/flow_pulse_generator` 사용 | |
| 1초 펄스 수, L/min, 누적 L 확인 | 계산값과 실측 일치 | |
| 주파수별 펄스 누락률 측정 | 낮을수록 좋음, 손실 있으면 대안 검토(`open-decisions.md`) | |
| 재부팅 후 누적값 복원 | NVS에서 복원 | |

## 단계 5: 현장 시험 (LED/저전압 부하로 먼저)

`docs/wiring.md`의 "현장 전환 및 롤백 절차"를 따르세요.

| 장애 시나리오 | 기대 결과 | 실제 결과 |
|---|---|---|
| 인터넷 차단 | 로컬 제어/안전기능 계속 | |
| MQTT 서버 차단 | 상동 | |
| Ethernet 케이블 분리 | 상동, 재부팅 없음 | |
| RS485 A/B 분리 | 팔 노드 안전 OFF | |
| 메인 노드 전원 재부팅 | 부팅 시 전부 OFF, 이후 정상 복귀 | |
| 팔 노드 전원 재부팅 | 상동 | |
| 유량계 선 단선 | 값이 0 또는 에러 상태로 명확히 표시(있는 척 안 함) | |
| 잘못된 명령 연속 입력 | 무시, 정상 명령엔 계속 응답 | |
| 구역A 로컬재생 (인터넷 3~5분 이상 차단) | 정지상태부터 안전하게 재생 시작, 서버 복귀 시 즉시 서버 우선 | |
| 포깅 중 인터넷 차단 | 포깅은 안전 정지(재생 안 함) | |

## 완료 조건 체크

작업지시서 13번 항목을 그대로 사용:

- [ ] 메인용/팔 노드용 펌웨어 각각 경고 없이 빌드
- [ ] 공식 보드 핀이 소스 한곳에 상수화됨(`board_pins.h`)
- [ ] 메인은 W5500 이더넷으로 MQTT TLS 연결
- [ ] 팔 노드는 WiFi 없이 RS485만으로 CH1~CH3 제어
- [ ] 기존 MQTT 명령/상태 토픽 호환
- [ ] 명령 후 팔 노드 실제 상태 확인(readback)
- [ ] 인터넷/MQTT 장애 중 로컬 제어가 멈추지 않음
- [ ] 네트워크 장애만으로 재부팅하지 않음
- [ ] RS485 장애 시 팔 노드가 설정 시간 내 안전 OFF
- [ ] 밸브별 90초 안전 타임아웃 동작
- [ ] 유량계 펄스 시험 결과 문서화
- [ ] 실제 인증정보가 저장소에 없음(`config.h`는 `.gitignore`)
- [ ] 배선표/업로드 설명 제공
- [ ] 각 장애 시험 기대/실제 결과 표 작성 완료
